# 单元依赖与交付顺序

## 依赖矩阵

| 提供单元 | 消费单元 | 契约/资源 | 依赖级别 | 验证点 |
|---|---|---|---|---|
| U1：游戏领域逻辑 | U2：浏览器体验与 3D 场景 | `GameState`、`GameAction`、`Transition`、`GameViewModel`、关卡/姿态函数 | 阻塞 | U1 示例测试和 PBT 全部通过；公开接口稳定 |
| U2：浏览器体验与 3D 场景 | U1：游戏领域逻辑 | 白名单用户动作与单调 `TICK` 时间 | 运行时调用 | U2 不直接修改或复制领域规则 |
| U1 + U2 | 构建与测试 | 静态运行入口、测试命令、场景交互 | 集成 | 静态服务浏览器冒烟全场景通过 |

## 顺序计划

1. **U1 功能/NFR 设计 → 代码与测试**：先冻结公开领域契约；使用 Node 运行示例测试与 `fast-check`。
2. **U1 检查点**：所有领域测试通过，确定性种子/关卡和 reducer 转换满足性质；确认没有浏览器副作用。
3. **U2 功能/NFR 设计 → 代码与测试**：将 U1 契约接入 React/R3F、HUD、音效和受控错误边界。
4. **U2 检查点**：启动和资源清理正确；UI/R3F 不违反单向数据流；安全/供应链要求已实现或在构建说明中可验证。
5. **集成检查点**：以静态 HTTP 服务器托管页面，人工或自动化冒烟验证开始、有效跳跃、掉水、通关、失败、重玩与静音。

## 共享资源与通信

- 不存在跨网络、数据库、API、队列或独立部署资源。
- 共享契约为同一 `game.js` 内显式定义的只读对象和导出函数；U2 不持有其可变引用。
- 测试可使用 U1 可注入种子和时间；UI 不产生自己的随机规则。

## 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| U2 在 U1 契约前实现 | 高 | 先完成 U1 检查点；仅在稳定接口后实现 U2。 |
| 场景帧与 reducer 时间不一致 | 中 | 由 GameSessionService 发送单调 `TICK`；R3F 仅做视觉插值。 |
| 重玩导致副作用重复 | 中 | 统一由 GameSessionService.dispose 与 React/R3F 卸载流程清理。 |
| CDN/R3F 资源受 CSP 或完整性限制 | 中 | 固定版本、可信源和部署安全头/完整性复核步骤纳入 NFR/构建阶段。 |
