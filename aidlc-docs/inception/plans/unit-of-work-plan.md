# 单元工作计划

## 分解建议

建议采用已批准的两单元、顺序交付方式：

1. **U1：游戏领域逻辑** — 纯函数的关卡生成、运动学、状态 reducer、得分和 PBT。它先交付稳定的数据/动作契约。
2. **U2：浏览器体验与 3D 场景** — React、React Three Fiber、HUD、R3F 交互、音效、错误边界和资源清理。它消费 U1 的公开契约。

这不是两个独立部署服务，而是同一静态应用中的两个逻辑开发单元；它们避免 UI 代码与游戏规则相互耦合，并让 U1 在无浏览器环境中先被严格验证。
