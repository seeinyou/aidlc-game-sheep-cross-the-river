# U1 NFR 设计模式

## 纯领域核心模式

- `LevelFactory`、`BoardKinematics`、`ScorePolicy`、`GameReducer` 和 `toViewModel` 接受完整显式输入并返回新值；不读写模块级会话状态或浏览器全局对象。
- 时间通过 `TICK.elapsedMs` 输入，种子通过 `baseSeed` 输入；相同输入产生相同输出。
- 状态使用不可变替换；避免跨 reducer 调用共享可变对象。测试使用深冻结/快照比较，防止意外变异。

## 总函数与安全失败模式

- 动作由固定判别联合表示；每个 reducer 分支在未知、非法或不合时机输入时返回不变状态并可产生受限 `reject` 效果。
- 数值边界（生命、分数、时间、关卡和平台尺寸）在创建和状态转换入口处验证/夹紧；不允许 `NaN`、无穷或未定义值进入 GameState。
- 效果仅使用固定名称与键；不承载异常、URL、原始输入或秘密。
- 不捕获后再吞掉编程错误：领域校验错误安全返回；测试/开发错误必须在测试中可见。

## 性能抽样模式

1. 以固定代表性输入预热每个受测函数，排除首次加载/JIT 启动噪音。
2. 对 `createLevel`、`reduce`、`toViewModel` 各运行 1,000 次，使用 `node:perf_hooks.performance.now()` 记录每次耗时。
3. 排序耗时，计算第 95 百分位；**p95 必须小于 5 ms** 才能通过。
4. 输出 p50、p95、最大值和环境信息；最大离群值用于诊断，不单独使门禁失败。
5. 基准使用固定种子与已知动作，禁止与网络、DOM 或真实时钟耦合。

## 测试金字塔与 PBT 模式

- **示例层（node:test）**：固定情景，记录业务规则、回归用例和玩家关键路径。
- **属性层（fast-check）**：复用领域 generators，验证关卡可达性、确定性、范围、状态模型/参考 oracle 和视图模型纯度。
- **性能层**：独立的有界抽样测试，避免与随机 PBT 性能混杂。
- PBT 保持默认 shrinking；失败时由框架输出种子与最小反例。发现的 PBT 缺陷需将反例转为永久示例测试。

## 依赖与供应链模式

- `package.json` 中所有第三方依赖精确固定，`package-lock.json` 必须提交；干净安装只使用 `npm ci`。
- 依赖来源是官方 npm registry；新增包需要用途记录且通过未使用依赖审查。
- 质量顺序：`npm ci` → 格式/静态检查 → 示例测试 → 属性测试 → 性能抽样 → `npm audit --audit-level=high` → SBOM。
- `npm audit` 高严重度发现阻止通过；首选升级或移除。若没有立即修复，必须记录范围/缓解/过期日期并获得用户明确风险接受，不能静默跳过。
- SBOM 生成文件应标明工具、时间与 lockfile 来源；在构建/测试阶段验证其存在。

## 可维护性与追溯模式

- 每个公开 U1 函数保留对领域规则和测试文件的注释/命名追溯。
- 业务规则、示例测试和 PBT 使用一致术语（关卡、主路径、落点、生命、效果）。
- 领域 API 仅在 `game.js` 的 U1 段导出，U2 只能消费只读数据和动作。

## 不适用模式

- 重试、断路器、缓存、队列、数据库副本、分布式锁、服务自动扩缩和灾备：N/A；U1 是无 I/O 的进程内纯逻辑。
- 用户认证、授权、网络加密、API 限流、远程结构化日志/告警：N/A；U1 无网络端点或远程服务。
